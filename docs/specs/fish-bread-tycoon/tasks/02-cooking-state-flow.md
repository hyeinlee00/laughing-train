# 02 — 붕어빵 조리 상태 흐름

## Outcome

각 틀을 클릭하거나 대응 키보드 숫자를 누르면 붕어빵이 `빈 틀 → 반죽 →
굽는 중 → 뒤집기 타이밍 → 마무리 굽기 → 완성` 순서로 진행된다. 뒤집기
타이밍에 입력하면 정확도에 따라 PERFECT/GOOD/EARLY/LATE로 판정되고, 너무
늦게 방치하면 탄 상태가 되어 더 이상 판매할 수 없다. 9개의 틀은 서로
독립적으로 동시에 다른 상태를 가질 수 있다.

## Blockers

01-screen-shell-and-controls — 틀 UI와 클릭/키보드 입력 이벤트가 있어야
조리 상태 진행을 트리거하고 화면에 표시할 수 있다.

## Acceptance criteria

- [x] 빈 틀을 클릭/키 입력하면 반죽 상태로 전환된다.
- [x] 반죽 상태는 일정 시간 후 굽는 중 상태로 자동 전환된다.
- [x] 뒤집기 타이밍이 되면 화면에서 식별 가능하게 표시된다.
- [x] 뒤집기 타이밍에 입력하면 PERFECT/GOOD/EARLY/LATE 중 하나로 판정되어
      화면에 표시된다.
- [x] 뒤집기 타이밍을 놓치고 방치하면 탄 상태가 되고, 탄 붕어빵은 판매
      동작의 대상이 되지 않는다.
- [x] 서로 다른 틀에서 동시에 서로 다른 조리 상태가 독립적으로 진행된다.

## Constraints

붕어빵의 상태별 비주얼은 `assets.md`의 실제 이미지 없이 상태명 텍스트나
색상 구분 등의 플레이스홀더로 표현한다 (spec.md 공유 제약).

## Verification

- 자동 테스트: 상태 전이 함수가 EMPTY→BATTER→COOKING→READY 순서를
  올바르게 따르는지 검증.
- 자동 테스트: 뒤집기 타이밍 판정 함수의 PERFECT/GOOD/EARLY/LATE 경계값을
  각 경계 안팎의 입력으로 검증.
- 자동 테스트: 뒤집기 타이밍을 넘긴 경과 시간 입력 시 BURNT로 전환되는지
  검증.
- 브라우저 확인: 여러 틀을 동시에 조작해 상태가 서로 독립적으로 진행되는지
  확인.
