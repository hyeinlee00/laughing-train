# 03 — 손님 주문과 판매

## Outcome

화면에 현재 손님의 주문 수량(1~4개)이 표시된다. 완성된 붕어빵을 주문
수량만큼 모으면 판매할 수 있고, 판매가 이뤄지면 매출이 오르고 다음 손님이
즉시 등장한다. 주문 수량보다 1개를 더 제공하면 서비스 보너스를 받는다.

## Blockers

02-cooking-state-flow — 판매 대상이 되는 완성(READY) 붕어빵 상태가 있어야
판매 로직을 검증할 수 있다.

## Acceptance criteria

- [x] 게임 화면에 현재 손님과 필요한 붕어빵 수량이 보인다.
- [x] 완성된 붕어빵이 주문 수량 미만이면 판매할 수 없다.
- [x] 완성된 붕어빵이 주문 수량 이상이면 판매 동작을 수행할 수 있다.
- [x] 주문 수량만큼 정확히 판매하면 기본 매출(개당 500원 × 수량)이 더해진다.
- [x] 주문 수량보다 1개를 더 제공하면 서비스 보너스가 추가로 매출에
      더해진다.
- [x] 판매(또는 주문 완료)가 끝나면 다음 손님과 새 주문이 즉시 나타난다.

## Constraints

손님 캐릭터는 `assets.md`의 실제 이미지 없이 이름/아이콘 텍스트 등의
플레이스홀더로 표현한다 (spec.md 공유 제약).

## Verification

- 자동 테스트: 주문 수량과 보유한 완성 붕어빵 수를 입력으로 판매 가능 여부
  판정 함수를 검증.
- 자동 테스트: 기본 판매 금액, 서비스 보너스 조건과 금액 계산 함수를 여러
  수량 조합으로 검증.
- 브라우저 확인: 주문 발생 → 붕어빵 완성 → 판매 → 다음 손님 등장까지 한
  사이클을 직접 확인.
