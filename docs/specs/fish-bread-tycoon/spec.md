# 붕어빵 장인 — MVP 스펙

부제: 60초 안에 얼마나 많이 벌 수 있을까?

## 사용자에게 보이는 결과

- 시작 화면에서 게임 방법을 길게 읽지 않고 바로 "게임 시작"을 눌러 진입한다.
- 게임 화면에서 6개의 붕어빵 틀을 동시에 관리한다: 반죽 넣기 → 굽기 → 타이밍에
  맞춰 뒤집기 → 완성 붕어빵 꺼내기 → 손님 주문 수량만큼 판매 → 매출/콤보 획득.
- 60초 동안 시간이 지날수록 조리 시간이 짧아지고 주문 수량과 손님 등장 속도가
  늘어나 여러 틀을 동시에 처리해야 하는 긴장감이 커진다.
- 60초가 끝나면 결과 화면에서 총 매출, PERFECT/GOOD/BURNT 횟수, 최대 콤보,
  등급을 보고, 개인 최고 기록과 비교한 뒤 즉시 "다시 굽기"로 재도전한다.
- 마우스 클릭과 키보드(1~6) 중 무엇을 쓰든 동일하게 플레이할 수 있다.

## 승인된 범위

**조리 시스템**
틀 상태는 `빈 틀 → 반죽 → 굽는 중 → 뒤집기 타이밍 → 마무리 굽기 → 완성 →
(방치 시) 탄 상태` 순서로 흐른다. 뒤집기 타이밍의 정확도에 따라
PERFECT/GOOD/EARLY/LATE로 판정하며, 너무 늦으면 탄다. 탄 붕어빵은 판매할 수
없고 콤보를 끊는다.

**손님 · 판매 · 점수**
한 번에 손님 한 명의 주문(1~4개)만 활성화되고, 완료 즉시 다음 손님이 등장한다.
주문 수량만큼 기본 판매하고, 1개를 더 제공하면 서비스 보너스를 받는다.
PERFECT가 연속되면 콤보가 오르고, EARLY/LATE/탄 붕어빵/주문 실패는 콤보를
초기화한다. 붕어빵 1개 기본가는 500원이며, 서비스 보너스와 콤보 보너스가
누적 매출에 더해진다.

**시간 · 난이도**
게임은 정확히 60초이며 0~20초/20~40초/40~60초 구간마다 조리 시간, 주문 수량,
손님 등장 속도가 단계적으로 빡빡해진다. 시간이 끝나면 조작이 즉시 막히고
결과 화면으로 전환된다.

**결과 화면**
총 매출, PERFECT/GOOD/BURNT 집계, 최대 콤보, 매출 구간별 등급(견습생~전설의
붕어빵 장인)을 보여주고 즉시 재도전할 수 있다.

**조작**
마우스 클릭과 키보드 1~6이 동일한 동작을 수행한다. 화면의 6개 붕어빵 틀
배치는 넘버패드(넘버락) 숫자 배열과 동일해야 한다 — 윗줄이 4·5·6, 아랫줄이
1·2·3 순서로 배치되어 키 위치와 화면 위치가 손 감각적으로 일치해야 한다.

**인터랙션 피드백**
PERFECT/GOOD/BURNT/콤보 상승 시 즉각적인 시각·효과음 피드백(팝업, 파티클,
숫자 튀어오름, 연기 등)으로 "누르는 순간의 쾌감"을 만든다.

**비주얼 방향**
2000년대 한국 피처폰 게임의 복고 감성을 현대적 웹 UI로 재해석한다(기존 게임
그래픽/사운드를 복제하지 않음). 어둡거나 따뜻한 포장마차 톤, 큰 숫자, 고대비
UI, 6개 틀이 화면의 가장 큰 영역을 차지하는 레이아웃.

## 관찰 가능한 인수 기준

- 처음 보는 사람이 설명 없이 5초 안에 무엇을 해야 하는지 이해하고, 바로
  시작 버튼을 눌러 진입한다.
- 마우스만으로 완전히 플레이할 수 있고, 키보드 1~6으로도 동일하게 플레이할
  수 있다.
- 모든 클릭/키 입력에 즉각적인 시각 피드백이 있다.
- 게임 후반부(40~60초)에 여러 틀을 동시에 처리해야 하는 순간이 실제로
  발생한다.
- 60초 종료 시 결과 화면에서 "한 판 더" 하고 싶은 느낌이 들고, 재도전
  버튼을 눌러 즉시 다시 시작할 수 있다.
- 30초 내외의 짧은 시연만으로 옆에서 보는 사람이 게임의 재미를 이해할 수
  있다.

## 확정된 제약과 근거

- **데스크톱 우선, 모바일은 깨지지 않게만**: 데스크톱 브라우저를 1순위로
  개발하되, 모바일 브라우저에서도 레이아웃이 깨지지 않고 탭/클릭만으로 완전히
  플레이 가능해야 한다. 다만 터치 제스처나 모바일 전용 레이아웃 세밀 조정은
  MVP 범위 밖이다. (근거: `PRODUCT.md`의 "데스크톱·모바일 모두 반응형" 경계와
  4시간 개발 제한을 절충하기 위해 사용자와 합의함.)
- **키보드-화면 배치 일치**: 6개 틀의 화면 배치는 넘버패드 물리적 배열(위:
  4·5·6, 아래: 1·2·3)과 반드시 일치해야 한다. (근거: 사용자가 손 감각의
  직관성을 위해 명시적으로 요구함.)
- **서버 없이 로컬만 사용**: 점수/기록은 브라우저 로컬에만 저장하고, 비교
  대상은 자기 자신의 이전 최고 기록뿐이다. 서버, 로그인, 온라인 랭킹은 두지
  않는다. (`PRODUCT.md` 경계 재확인.)
- **게임 결과물에 AI 기능 없음**: 판단/추천/생성 등 AI 기능을 게임 자체에
  넣지 않는다. (`PRODUCT.md` 경계 재확인.)
- **구현 중에는 리소스를 플레이스홀더로 대체**: `assets.md`에 명시된 이미지
  리소스(붕어빵 상태별 이미지, 손님 캐릭터, 조리 이펙트, 배경 등)는 별도
  컨텍스트에서 나중에 제작된다. 게임 코드 구현 단계에서는 이 리소스가 아직
  없다고 가정하고 색상 블록/텍스트 라벨 등 단순 플레이스홀더로 대체하며,
  실제 리소스가 준비되면 교체한다. (근거: 리소스 제작과 게임 코드 개발을
  병렬로 진행하기 위해 사용자와 합의함.)

## 가정

- UI 언어는 한국어만 지원한다 (`PRODUCT.md`에서 이미 확정된 가정).
- 사운드는 폴리싱 우선순위가 가장 낮다 — 없어도 되고, 시간이 남을 때 마지막에
  추가한다 (`PRODUCT.md`에서 이미 확정된 가정). 효과음을 넣는다면 기존 게임
  사운드를 복제하지 않고 무료 소스나 직접 생성한 소리를 쓴다.
- 매출 구간별 등급 컷오프(예: 0~2,999원 견습생 등)는 잠정치이며, 실제 플레이
  후 밸런싱 과정에서 조정될 수 있다.
- 시간대별 난이도 수치(조리 시간, 주문 수량, 손님 속도)는 사용자가 제시한
  구간별 방향을 초안으로 삼되, 플레이 테스트 후 조정될 수 있다.

## 범위 밖 (하지 않을 것)

4시간이라는 개발 시간 제한 안에서 핵심 게임 루프의 완성도에 집중하기 위해
다음은 만들지 않는다: 로그인/회원가입, 서버 저장, 온라인 랭킹, 상점, 캐릭터
성장, 장비 업그레이드, 여러 종류의 붕어빵, 재료 시스템, 직원 고용, 가게 확장,
수십 개의 스테이지, 복잡한 경제 시스템, AI 기능, 실시간 멀티플레이.

## 미룬 사항

- **비주얼 에셋**: 붕어빵/틀/UI 등의 이미지 리소스는 사용자가 별도 스펙으로
  제공할 예정이며 이번 스펙에는 포함하지 않는다.
- **효과음 구현 방식**: 자체 생성할지 무료 소스를 쓸지는 아직 정하지 않았다
  (사운드 자체가 최저 우선순위라 지금 결정하지 않아도 된다).
- **정확한 등급 컷오프와 난이도 수치**: 플레이 테스트를 거쳐 밸런싱 단계에서
  확정한다.

## 남은 위험

- 4시간이라는 매우 타이트한 시간 안에 핵심 루프(Priority 1~2)를 넘어 손맛
  피드백(Priority 3)까지 완성하지 못할 위험이 있다 — 시간이 부족하면 폴리싱
  (Priority 4)부터 덜어내는 것으로 완화한다.
- 모바일 브라우저에서 레이아웃이 실제로 깨지지 않는지는 아직 실기기로
  검증되지 않았다.
- 넘버패드 배치(위 4·5·6 / 아래 1·2·3)와 화면 그리드가 실제로 직관적으로
  느껴지는지는 플레이 테스트로 확인이 필요하다.
